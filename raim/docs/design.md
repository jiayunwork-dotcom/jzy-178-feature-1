# 设计说明：多模定位/完好性与跨历元状态管理

## 1. 单历元层（多模）

### 1.1 多模观测模型与时间基准（本版关键变化）

下一阶段试飞的接收机同时收 GPS、Galileo、北斗三套系统。各系统的系统时
（GPST / GST / BDT）之间有偏差，同一台接收机对每套系统看到的“钟差”并不相同。
因此观测模型除三维位置外，**为每个参与系统各设一个钟差未知量**：

```
y = G·dx + ε
G 每行 = [-ux -uy -uz | δ_gps δ_gal δ_bds]   （仅该星所属系统那一列为 1）
W = diag(1/σ_i²)
dx = (GᵀWG)^{-1} GᵀW y
```

- 未知量个数 `m = 3 + k`，`k` = 本历元实际参与的系统数；自由度 `dof = n - m`。
- **基准取 GPS 时**：GPS 列恒为 1，其系数就是（旧版意义上的）接收机钟差；
  Galileo/北斗列的系数是该系统时相对 GPS 时的系统间偏差（GGTO/钟差，米）。
- GPS 不参与的历元以“本历元规范顺序第一的系统”为基准（其钟差列恒为 1），
  其余列仍是相对偏差；本阶段输入总含 GPS，该分支只是完备性处理。
- 同一历元三套系统的伪距一起进入定位、检测、排除、保护级，不再只认 GPS。

只含 GPS 时 `k=1, m=4`，矩阵就是旧版的 `[-ux -uy -uz 1]`；通用解算的列归一化、
部分选主元高斯消元/高斯-若尔当求逆走**逐位相同的运算序列**，因此 GPS-only 的
定位、残差、SSE、阈值、HPL 与升级前严格一致（由既有全套测试与
`cmd/replaydemo` 黄金文件 `docs/replay_results.json` 钉死）。

迭代初值、收敛判据（1mm / 10 轮）、WGS84 换算与旧版一致。

### 1.2 系统间时间偏差的建模选型：逐历元自由估计（白模型）

两套系统时的偏差有两种可行处理，本版选择**方案 A：每个历元把它当作新的自由
未知量重新估计**，不跨历元携带。方案 B 是作为缓慢变化状态跨历元平滑/滤波
（带先验、随机游走、Kalman 等）。选择理由、代价与 B 更优的场景如下。

**选 A 的理由（与本阶段的完好性目标一致）：**

1. **台阶立即吸收，位置绝不被带走。** 某系统全部伪距同加一个常数（系统时跳变、
   重捕、粗时间），在白模型下只是该系统钟差列换一个值，第一个历元就完全吸收，
   位置与残差逐位不变，也不会污染卡方统计量——天然满足
   “Galileo 全部伪距同加常数、位置不变”，且**无需过渡历元**。带先验的 B 会把
   台阶拉进若干历元的残差，需要专门处理（放大过程噪声、重新收敛），处理不当
   既会瞬时带偏位置，还可能把台阶吃进 SSE 造成漏检或误警。
2. **不新增跨历元状态，也就没有新的一致性面。** 批量与逐历元一致、重启续跑一致
   只需要既有的隔离/告警状态满足；时间偏差每历元自包含，断续可见后回来首历元
   即正常，不存在“先验陈旧”问题。
3. **首历元即满精度。** 冷启动、会话中途切入新系统都不依赖历史，无需热身。
4. **检测理论保持精确。** 每历元普通最小二乘，加权 SSE 在 H0 下严格服从
   χ²(n−m)，卡方阈值、斜率法 HPL 的推导无需近似或修改。
5. **冗余代价在本场景可承受。** 多一个系统只多吃 1 个冗余（多 1 个未知量）。
   三系统、每系统 9 星时 dof=21，余量充足。

**A 吃亏的地方：**

- 每个非基准系统只有 1 颗可见星时，该星的全部信息都花在估钟差上，对位置/冗余
  没有贡献（这是物理事实，B 用先验时可以“借历史”把这颗星的位置信息用起来）。
- 不利用系统间偏差“短期近似恒定”这一先验信息：短历元、低冗余时，A 的钟差与
  位置估计噪声比 B 大（参数估计多了自由度）；A 的位置方差为
  (GᵀWG)⁻¹ 的位置块，随 m 增大略升。
- A 对粗差没有平滑作用：它只负责“不误事”，不会从历史中把偏差估得更稳。

**换成 B（跨历元携带）会更好的场景：**

- 可见星长期紧张（如高纬/遮挡环境，某系统经常只有 1–2 颗），需要用历史先验把
  这些星的位置信息“变现”，提高可用性与冗余；
- 历元间隔短、钟差稳定，且应用愿意用瞬时收敛速度换长期精度（如精密相对定位、
  紧组合）；
- 需要对系统间偏差本身输出平滑可预测的量（故障诊断、钟差监测）。

若将来转 B：时间偏差要进持久状态，受批量/逐历元一致与重启续跑一致约束；
并且必须对“系统时台阶”设置足够的过程噪声或台阶检测，否则会以位置瞬差为代价。
**台阶反应（B）**：以一阶马尔可夫/随机游走为例，台阶后该系统钟差以时间常数
τ 指数逼近新值，位置在过渡期出现与几何相关的瞬态偏差，约 3τ–5τ 个历元回到
稳态；本版 A 下该过渡长度为 **0 个历元**（见测试
`TestMultiSystemGalileoStepPositionInvariant` 钉死的行为）。

### 1.3 检测

加权残差平方和

```
SSE = Σ_i (r_i / σ_i)²   ~ χ²(n−m)  (H0 无故障)，m = 3 + k
```

阈值 `T` 满足 `P(χ²(n−m) > T) = Pfa`（卡方分位数由 `pkg/chisq` 反解，自研）。

- `n − m < 1`（冗余为 0）：只有定位、无冗余，结果标 `unavailable`；
- 有冗余且 SSE ≤ T：`ok`；
- SSE > T：检出故障。

### 1.4 排除

- 剔后须仍有至少 1 个冗余（`n−1 ≥ m`）才能再检，即需要 `n ≥ m+2` 才能排除；
  只含 GPS 时即旧规则的“少于 6 星无法排除”。
- 逐星剔除重解，对 n−1 颗星子集重算 SSE 与对应自由度、阈值；
- **恰有一颗**星剔后通过检验才唯一排除，报 `excluded` 并采用剔星干净解；
  没有剔法通过（疑似多星）或多颗剔后都通过（无法唯一识别），报 `detected`，
  不用任何剔星解。
- 剔星按“**系统+编号**”区分：GPS 3 号出偏差只能剔 GPS:3，北斗 3 号是另一颗星，
  照常参与（`TestMultiSystemGPS3ExcludedBDS3Kept`）。

### 1.5 水平保护级 HPL

仍用 Brown/Sturza 斜率法 `HPL = slopeMax · √λ`，但几何量全部基于 m 维
（3+k）法方程逆矩阵：`A = (GᵀWG)⁻¹GᵀW`、残差投影 `S = I − G(GᵀWG)⁻¹GᵀW`
均为多钟差列版本；`√λ` 仍由 `P(χ'²(dof,λ²) ≤ T) = Pmd` 反解，
排除成功后用剩余星、对应自由度与门限。GPS-only（m=4）与旧实现逐位相同。

## 2. 跨历元状态管理

### 2.1 隔离 / 恢复（按“系统+编号”）

某历元被唯一排除的**（系统,编号）**进入隔离集合。之后每个历元：

- 隔离星**不参与**定位解；
- 但仍用“含该星的全星解”（多模模型）计算恢复检验量：
  - 该星标准化残差 |r|/σ 不超单星门限 √T；
  - **且**把它加回后整体 SSE 通过卡方检验；
- 两条件须**连续**满足 `isolation.min_epochs` 个历元才解除；
- 任一历元不满足，或该星本历元不可见，计数清零。

解除发生在解算之后，下一历元才重新参与。隔离状态的键是 `SatID{System,ID}`，
落盘为 `"GPS:4"` 文本键；升级前旧文件里的裸编号键 `"4"` 读取时按 GPS 解释。

> 时间偏差是白估计，**不构成**跨历元状态；隔离/告警是本服务仅有的跨历元状态。

### 2.2 告警判定（与上一版一致）

告警条件是“检测失败（检出无法排除 / HPL > HAL）”；成功排除单星后采用干净解，
不再告警。运行档 `alert.mode` 三选一：

1. `snapshot`：一个历元超限即告警，下一历元正常即撤；首报最快、误警最多。
2. `persistence`：连续 `confirm_epochs` 超限才拉起，连续 `clear_epochs` 正常才撤；
   误警最少、首报最多滞后一个确认窗口。
3. `combined`（内置默认）：普通超限走窗口；**恶劣超限**
   （SSE ≥ gross_factor×T 或 HPL ≥ gross_factor×HAL）立即告警，撤警仍走窗口。

### 2.3 回放数据对比

告警三方式的固定种子回放对比（本版结果与上一版逐值相同）见
[replay_results.json](replay_results.json)，由 `cmd/replaydemo` 生成。

### 2.4 误警口径（不变）

- 在线服务（`session.Stats.FalseAlarms`，无地面真值）：一个告警片段内从未识别出
  任何故障（无检测/排除事件）才算误警。
- 回放分析（知道注入真值）：告警片段与真实持续故障窗口不相交才算误警。

## 3. 每历元输出：系统钟差与参与情况

每个历元记录新增 `system_clocks`，按固定顺序 GPS/GAL/BDS 各一项：

```json
"system_clocks": [
  {"system":"GPS","clock_bias":12.3,"used":true,"sat_count":9},
  {"system":"GAL","clock_bias":-45.6,"used":true,"sat_count":9},
  {"system":"BDS","clock_bias":78.9,"used":true,"sat_count":9}
]
```

- `clock_bias`：相对 GPS 时的偏差（米），GPS 项即接收机钟差（也仍写在旧字段
  `clock_bias`）；未参与的系统 `used=false`、值为 0、`sat_count=0`。
- 排除成功后该表对应**报告解**（剔星干净解），`sat_count` 为该系统实际入解星数。
- 所有按星的字段（`sat_results`、`trials`、`isolated`、`excluded_*`）都带系统：
  GPS 为兼容旧消费方，落盘时省略 `system`（隔离引用直接写裸编号），
  非 GPS 写 `"system":"GAL|BDS"`。

## 4. 会话与持久化、向后兼容

- 会话创建时绑定运行档；可批量（≤3600，整段原子）也可逐历元提交；两条路径与
  重启续跑都走同一个 `Service.Step`，逐项一致。白估计不增加跨历元状态，
  一致性要求只由既有隔离/告警状态承担。
- **没有系统标识的星一律按 GPS**：旧客户端、升级前落盘的会话/自建运行档可直接
  继续提交。
- **已经落盘的历元记录不能改写**：读盘时保留旧记录的原始 JSON，再次写盘时原样
  输出（`EpochRecord` 的 raw 透传）；新历元用升级后格式追加。旧记录没有
  `system_clocks`/`excluded_system`，读取后为零值，不回补、不落盘。
- 只含 GPS 的输入（新/旧会话）逐历元定位、检测、排除、保护级、隔离、告警与
  统计口径与升级前一致：m=4 运算序列逐位相同，且有黄金回放文件与全套旧测试。
- 时间戳去重（409）/倒退（422）、原子写（临时文件+rename）、告警持续性判定、
  会话统计口径均不变。

## 5. 输入校验（错误指到具体字段）

在旧有规则（不足星数、编号重复、NaN/Inf、σ≤0、概略近地心、几何奇异）之上新增：

- **系统标识不认识要拒**：只接受精确大写 `GPS`/`GAL`/`BDS`，错误指到
  `satellites[i].system`；空标识由兼容逻辑按 GPS（不拒）。
- **同一系统内编号重复要拒，跨系统同号不算重复**：重复指到
  `satellites[i].id`。
- 定位最少星数随系统数变为 `3+k`（3 个位置 + 每系统 1 个钟差）。
- 批量提交时字段路径统一带历元下标，如 `epochs[3].satellites[1].system`。
